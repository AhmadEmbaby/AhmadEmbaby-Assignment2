2- git merge  vs  git rebase 
______________________________

كل واحد منهم بيعمل اييه ؟؟
اولا 
Merge 
بيدمج فرعين ببعض ولكن من غير ما يغير في الهيستوري .. يعني الكوميتس الي علي الفرع الثاني بتكون ظاهره وموجدة زي ما هي متغيرتش وواضح حصل دمج امتا 
ثانيا
Rebase 

بيدمج بردو فرعين ببعض ولكن بيغير في الهيستوري وبيعيد انشاء الكوميتس من تاني وده بيخلي ال 
main Becomes Linear 
وبالتالي انضف للقراءة وتقدر تفهم بسهوله ايه الي حصل من الصفر لغاية اخر كوميت لانهم ورا بعض 

سيناريو :

 انا شغال علي فرع جانبي وعايز ادمجه علي الفرع الرئيسي , قدامي خيارين اما اني اعمل 
Merge
 وده هيخلي تاريخ الهيستوري زي ما هو 
أو اني اعمل 
Rebase
وبكده الهيستوري هيكون 
Linear 
واضح وسهل اعرف ترتيب الكوميتس بالظبت من بداية المشروع لنهايته

4- git cherry-pick
______________________________


بيعمل إيه؟

بياخد كوميت معينة من فرع ثانوي تاني ويطبق التغييرات بتاعتها عندي من غير ما أدمج الفرع الثانوي كله
كله

سيناريو :

 عندي فرع فيه كذا تعديل لكن محتاج حاجه محدده موجود في كوميت واحدة بس بدل ما أعمل

Merge

للفرع كله  اقدر استخدم
git cherry-pick

على الكوميت دي بس ... بس ممكن يحصل مشكلة فلازم الحذر عند استعمالها

5- git clean
______________________________



بيعمل إيه؟

بيحذف الملفات ال

Untracked

اللي موجودة في ال

Working Directory

ومش متسجلة في

Git


سيناريو :

كنت بجرب حاجات في المشروع، واتعملت ملفات مؤقتة كتير ومش محتاجها.

بدل ما أحذفهم واحدة واحدة، أستخدم

git clean

علشان أنضف الملفات ال

Untracked

7- git blame
______________________________



بيعمل إيه؟

بيوضح مين آخر شخص عدّل كل سطر في ملف، ومعاه ال

Commit

اللي حصل فيه التعديل.
سيناريو :
لقيت سطر في المشروع فيه مشكلة ومش فاهم ليه اتكتب بالشكل ده.

أستخدم

git blame
علشان أعرف مين عدّل السطر وأرجع لل

Commit

اللي عمل التعديل.
